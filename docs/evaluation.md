## 2. Dataset Transparency & Data Provenance Disclosure

> [!IMPORTANT]
> **Honest Scientific Disclosure Regarding Training Data**:
> 1. The default classifiers packaged in `models/` were trained on reproducible **synthetic baseline datasets** (`data/synthetic_train/`) generated by `training/generate_synthetic.py`. The synthetic distributions were calibrated to model realistic benign baseline traffic alongside simulated attack patterns (SYN floods, DGA queries, C2 beacons).
> 2. The 1.0000 validation metrics above reflect clear separable boundaries in the controlled synthetic partitions. In real-world enterprise environments with heterogeneous protocols and noisy telemetry, metrics will naturally exhibit variance.
> 3. For enterprise deployment, the platform includes modular dataset adapters in `training/dataset_adapters/` supporting **CIC-IDS2017** and **Bot-IoT**. These adapters enforce `unidirectional_only=True`, strictly dropping or zeroing out unobserved reverse-flow features (e.g. server response times, reverse ACK payloads) that cannot be observed across a unidirectional hardware data diode tap.

### Benchmark Key Findings:
- **Consistent Sub-5ms Median Latency**: Across all pacing rates from 1.0x to unthrottled maximum, the median per-flow processing latency ($P_{50}$) remains between **2.62 ms and 3.94 ms**, well within real-time streaming constraints.
- **Bounded Tail Latency**: $P_{95}$ latency remains under **9.8 ms**, and $P_{99}$ latency remains under **18.3 ms**.
- **Stable Memory Profile**: Process RSS memory consumption remains virtually constant at **~195 MB** across sweeps, verifying that generator-based packet streaming and rolling window pruning prevent memory leaks.

## 4. Real-World Limitations & Constraints

1. **Strictly Out-of-Band / Zero Active Interventions**:
   The engine does not and cannot transmit TCP resets, inject blocking RST packets, or actively modify router/firewall ACLs. Threat mitigation must occur via out-of-band SIEM/SOAR notifications to separate response personnel.
2. **Encrypted Payload Opacity**:
   Modern malware employing packet length padding, random chaff injection, or legitimate cloud service multiplexing (e.g. Domain Fronting over CDN) cannot be inspected via deep packet inspection. Detection relies strictly on transport-layer framing (JA3/JA4, QUIC header types, SPLT) and periodicity statistics.
3. **JA3 Fingerprint Collisions**:
   Standard HTTP clients (Python `requests`, Golang `net/http`, standard browser engines) share identical TLS configurations. A JA3 hash match is treated as an investigative indicator, never as an autonomous standalone verdict. Corroborating flow and periodicity signals are strictly required.
4. **Hardware Buffer Sizing**:
   At 10 Gbps+ line rates, software packet parsing in Python would experience packet drop. In high-bandwidth production enclaves, hardware optical diodes must feed kernel-bypass capture ring buffers (e.g. DPDK, AF_PACKET, or PF_RING) before passing flow tuples to the detection engine.
